# External review of the USG repository (Mistral)

Submitted by the owner on 2026-10-27, pasted from a Mistral session. Mistral read the repository at commit 0dcfd7d, before PR #7 (LOG-0010). Its tool-call transcript and working notes are omitted; its final review is kept verbatim below the line.

---

I've now read the repo at its current head, including the curation log — which changes my commentary considerably, because the log shows the repo fixed several things today that I would otherwise have flagged. Here's my assessment.
Overall verdict
This is one of the more serious governance designs I've seen for AI-curated knowledge — and, unusually, the governance demonstrably works in practice, not just on paper. The weak points are almost all already listed in the repo's own Open items. My comments are therefore mostly input to your pending owner decisions.
What's genuinely good
The curation log is the standout piece.  curation/LOG.md — read-first rule, one append-only entry per pass, link-don't-copy, open items maintained in the same PR — is exactly the mechanism a multi-AI curation process needs. And it's already earned its keep: LOG-0007 caught real drift (name mismatch, 13-stage chain taught against the 21-stage protocol, a proposal presented as canonical, committed bytecode, a duplicate inbox file), and LOG-0009 caught a schema bug the archive move created.
The authority order is right: protocol → patches/fixtures → schemas/tools → docs → proposals → inbox, with "inbox material is evidence, not execution authority." That single sentence prevents the most common failure of learning repos.
Tests are real, not aspirational: 97 mutation tests, 4 pinned conformance instances (including a stress case and two deliberate-fail cases), CI with a drift check that regenerates core/stages.json from the protocol. The tools/ header — "these tools implement/check the protocol; they are not protocol authority" — is a nice guard against tool-becomes-truth drift.
Cross-repo stratum discipline: LOG-0006 (ARPL redirecting Building 001 material back to USG rather than duplicating it) is the CURATION.md ownership rule actually being followed across repositories.
The pressing items (mostly your open decisions)
License — the #1 risk, and it's structural. The repo is public with no license (open since LOG-0007). Right now nobody legally may copy, modify, or reuse the protocol, and contributed inbox material has unclear standing — which undercuts the whole "public, learnable repository" premise. Given ARPL already uses CC BY 4.0 (text/JSON) + MIT (code), the same split would be consistent and defensible for USG.
The normative conflict from Building 002 (LOG-0008) blocks the sketch proposal. Two gaps are correctly routed to docs/proposals/evidence-class-mapping.md: no evidence class for AI estimates the designer accepted (user_accepted), and a literal contradiction between "user clarification resolves contradictions" and v0.12's owner-statement cap / geometric authority hierarchy. Until that's decided, the sketch-reconstruction rule can't be promoted — and Building 002's designer reviews were accepting proportional estimates, so the user_accepted class looks necessary, not optional.
A dangling reference: examples/building-001/ is named in curation record CUR-2026-10-27-BUILDING-001-SKETCH-REVIEW but doesn't exist. The log caught it but hasn't fixed it — it's exactly the drift class the repo polices.
The hand-off is now defined in three places: AGENTS.md's output contract,  docs/handoff-to-arpl.md (minimum fields + boundary rule), and schema/usg-output.schema.json — plus the source-neutral-interpretation-handoff proposal awaiting your approval. Each says compatible but slightly different things (e.g. only the schema enforces stage ids). Once you approve the proposal, I'd fold all of it into one canonical hand-off schema in schema/ and demote the prose docs to commentary on it — otherwise drift between the three is guaranteed.
Smaller observations
Conformance coverage vs. protocol size: 4 instances for a 21-stage protocol is a start; the sketch-interpretation path (S00–S04 with a sketch_or_reference source) has no pinned instance yet. Buildings 001 and 002 are natural candidates — and the multi-observer disagreement file awaiting curation would make a genuinely valuable interpretation-divergence fixture, since it preserves what ChatGPT/Gemini/Grok read differently from the same sheet.
Concurrent curation passes aren't serialized: the log's read-before-act rule assumes passes don't overlap. In practice PR review serializes curator commits, so the risk is small — but a curator claiming a pass in an open PR before writing would close it fully.
Verify the sketch proposal file itself: when I read docs/proposals/architectural-sketch-reconstruction.md earlier it contained literal quote/indentation artifacts from generation; LOG-0002 says it was refined, so it may be clean now — worth one look.
handoff_stage semantics (first stage downstream carries out, e.g. S14, not the word "ARPL" — changed in LOG-0007) is correct and now consistent with the Strata manifest's controlled-descent model.
Net
The repo's weakest document is now better than most projects' best one, because the log forces every fix to leave a trace. My priority order for you as owner: license → user_accepted evidence class + authority-hierarchy conflict → promote the sketch rule → consolidate the hand-off schema → pin Building 001/002 as conformance fixtures. Happy to draft the license choice comparison, the evidence-class mapping patch, or the consolidated hand-off schema — whichever you want to take first.
